{% load i18n icon_tags %} {% comment %} Chat composer. Anatomy, top to bottom inside the sticky dock: - **Context row** — repo · branch, plus the MR pill once one exists. It lives outside the composer box so it stays pinned with the dock and can never scroll away. Locked once a thread exists (the backend snapshots repo/ref on the first turn); before that it *is* the repo picker, and picking a repo is what ungates Send. - **Composer** — textarea, then one action row: the options trigger (``+``), the progress trigger (a pill that only renders when there is something to show), the model as plain text, and an icon-only Send / Stop. Everything that isn't acted on lives one tap away in a sheet, and nothing appears twice: env and MCP servers in the options sheet, todos and files changed in the progress sheet. Both sheets are bottom sheets below 1100px and popovers anchored above their trigger at or above it — same markup, only the container differs (see ``.composer-sheet`` in input.css). Typing ``/`` as the draft's first token opens the command autocomplete above the composer box (``_command_menu.html``). {% endcomment %}
