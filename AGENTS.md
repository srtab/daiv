# AGENTS.md

This file provides guidance to agents when working with code in this repository.

## Commands (verified)

```bash
make test                   # all unit tests with coverage (sets LANGCHAIN_TRACING_V2=false)
make lint-fix               # fix linting + formatting (ruff + pyproject-fmt; prefer over make lint)
make lint-typing            # type-check with ty (daiv/ only, excludes tests/)
make lint                   # check only, no fixes

# Single test / pattern
uv run pytest tests/unit_tests/accounts/test_views.py
uv run pytest tests/unit_tests/ -k "test_notes"

# Integration tests (separate from unit tests; requires DB)
make integration-tests      # runs with -m diff_to_metadata marker

# Translations
make makemessages && make compilemessages
```

- Unit tests live in `tests/unit_tests/` mirroring `daiv/` structure.
- `asyncio_mode = "auto"` — no need for `@pytest.mark.asyncio`.
- Python **3.14 only** (`requires-python = ">=3.14,<3.15"`). Ask uv for the specifier, never the bare `3.14` family: the family matches `3.14.0rc2`, on which pydantic cannot build a single model, so every test errors at collection. `.claude/hooks/session-start.sh` pins this for web sessions.
- Never edit `pyproject.toml` directly; use `uv add <pkg>==<version>` / `uv remove <pkg>`.

## Invariants / footguns

**Import paths** — `pythonpath = "daiv"` in pytest config; imports are `from automation.agent.graph import ...` (no `daiv.` prefix inside tests).

**Tool state updates** — tools cannot mutate `runtime.state` directly; return a `Command`:
```python
from langgraph.types import Command
from langchain_core.messages import ToolMessage

return Command(update={"key": value, "messages": [ToolMessage(content=output, tool_call_id=runtime.tool_call_id)]})
```
In unit tests that call tools directly, check `isinstance(result, Command)` and unpack manually.

**Accounts / auth**
- Standard email signup is **disabled** (`AccountAdapter.is_open_for_signup` → `False`).
- `AdminRequiredMixin` enforces `user.is_admin`; `user.is_last_active_admin()` guards deletion.
- `APIKey.objects.create_key(user, name, expires_at)` is **async** — use `async_to_sync` from sync contexts.

**Dependency management** — pin to exact versions (`==`), never edit `pyproject.toml` by hand. `parable` is git-pinned (not on PyPI); do not install it independently.

**Dependency upgrades — known blockers** (re-verify before re-attempting):
- **redis 8.x is blocked** by `redisvl` (`redis>=5.0,<8.0`), pulled transitively by `langgraph-checkpoint-redis`. The `uv.lock` dependency listing shows `{ name = "redis" }` without the bound, but `redisvl`'s actual requirement caps it. A `uv add redis==8.x` fails resolution with "langgraph-checkpoint-redis depends on redisvl>=0.15.0 → redisvl depends on redis>=5.0,<8.0". Wait for `redisvl` to ship a redis-8-compatible release before retrying.
- **mcp 2.0 is blocked** by `langchain-mcp-adapters` (pinned at the latest PyPI version, which targets mcp 1.x). mcp 2.0 *removes* (not deprecates) the v1 import paths — `mcp.server.fastmcp.FastMCP` → `mcp.server.mcpserver.MCPServer` — used directly in `daiv/mcp_server/server.py` and `daiv/mcp_server/auth.py`, and replaces the v1 `transport`+`ClientSession` layered client that `langchain-mcp-adapters.MultiServerMCPClient` drives (`daiv/automation/agent/mcp/`). Bump both together only when a mcp-2.0-compatible `langchain-mcp-adapters` is released.
- **Direct-dependency version checks** — direct deps are pinned with `==`, so `uv lock --upgrade --dry-run` reports *only* transitive updates. Query the PyPI JSON API (`https://pypi.org/pypi/<name>/json`, `info.version`) per direct dependency to find available direct updates. `django-extensions 4.1.0→4.1` and `python-decouple 3.8.0→3.8` are PEP 440-equal normalizations, not real updates.
- **redis-py 8.0 default `socket_timeout`** — when redis 8.x becomes upgradable, the async client in `daiv/core/redis.py` already passes `socket_timeout=None` explicitly (a no-op on 7.x, which defaults to `None`); keep it, since 8.0 changes the default to 5s and would cut short the blocking `PubSub.get_message(timeout=20)` / `xread(block=15000)` reads.

**GitLab is eventually consistent after a push** — the ref lands synchronously, but the work GitLab does *from* it (branch visibility to the MR-create endpoint, `refs/merge-requests/:iid/head`, the push's own pipeline) runs in async post-receive and has been observed ~37s late on `git.eurotux.com`. Three sites in `codebase/clients/gitlab/client.py` absorb it and they are deliberately **not** one mechanism: the clone-token and MR-create loops retry an *operation that errored* (narrow exception predicate, propagate or degrade to a typed error on exhaustion), while `_await_merge_request_head_ref` polls a *value on a call that succeeded* — an unsynced head ref returns a perfectly good commit that is simply the wrong one, which is why that bug was silent, and why exhaustion there proceeds anyway (`head_synced=False`) rather than raising. Reach for the matching shape, not the nearest neighbour. Nothing bounds the **sum**: one heal-path publish can serially sleep ~15s (clone token) + ~61s (MR create) + ~61s (head ref) inside `sync_to_async`, holding a `db_worker` process and — for the head-ref poll, which runs inside `GitMiddleware.aafter_agent` while the sandbox session is still open — a sandbox and its egress proxy. Size a fourth site against that total, and cap its tail: a doubling schedule spends longer asleep past a synced value than the value took to sync.

**Repository config** — `.daiv.yml` per repo cached 1 hour (`codebase/repo_config.py`). Invalidate via `RepositoryConfig.invalidate_cache(repo_id)`.

**Chat run streaming** — chat runs execute detached from the HTTP request (`chat/api/runner.py` spawns an asyncio task) and publish AG-UI events to the Redis stream `daiv:chat:run-events:<thread_id>:<run_id>` (`chat/api/relay.py`). SSE readers replay via `Last-Event-ID`; the terminal sentinel entry is `{"end": "1"}`. Client disconnects never stop a run — stopping is the explicit `POST /api/chat/cancel` (Redis flag checked at the next event boundary once the heartbeat interval elapses, plus an immediate local `asyncio.Task` cancel for the in-process run). Never revert to running the agent inside a `StreamingHttpResponse` generator.

**Rejoining a running chat turn** — a page load during a live run renders the checkpoint *and* replays the whole relay stream, so `_resumeRun` (`chat-stream.js`) must reconcile the two. Text and tool events dedupe by id (`turn.id` / `tool_call_id` are the same ids AG-UI carries), but **reasoning cannot**: `REASONING_*` events key on a per-thought id — the provider's, else a fresh `uuid4` upstream mints (`ag_ui_langgraph`) — which appears in no checkpoint. Replayed thoughts are therefore recognised *positionally*: a dedup hit proves every thought queued ahead of it was already rendered, so `_dropReplayedThinking` discards them (and rebuilds `_toolIndex`, which holds positions into `segments`). Without it the rejoin turn shows one thought per model call the run has already made, stacked consecutively because the events that separated them were deduped away. Segment clocks come from the AG-UI `timestamp` that `chat.api.runner._publish` stamps on every relayed event, never `Date.now()` — a whole run's frames arrive in one burst on rejoin, so a client clock labels every replayed thought with the 1s floor. `tests/unit_tests/chat/test_resume_replay.py` drives the real module under node and is the only coverage of this path.

**SSE plumbing is shared** — the response wrapper and frame vocabulary for every server-sent-events endpoint live in `core/sse.py` (`sse_response`, `data_frame`, `end_frame`, `retry_frame`, `KEEP_ALIVE_FRAME`, `STREAM_MAX_DURATION_S`), not per endpoint. Three streams use it: the chat run tail (`chat/api/views.py`), the session status stream (`sessions/views.py`) and the nav badges (`accounts/api/views.py`). `data_frame` owns the field syntax and the blank-line terminator — including the `id:`/`event:` heads and the JSON encoding, which each endpoint used to restate — and passes a `str` payload through unencoded, because the chat tail forwards what Redis handed it. `Cache-Control: no-cache` + `X-Accel-Buffering: no` are load-bearing — without them nginx buffers the response and nothing streams — and they were already drifting when each endpoint carried its own copy. A terminal `event: end` means *stop reconnecting*. What the **duration cap** means to the client is per endpoint, not shared: chat and nav close silently so EventSource reconnects (their resync), while `sessions/views.py` ends with an in-band `{"done": …, "complete": false}` that its JS re-subscribes on with a bounded budget — don't describe the cap as a silent close for all three.

**Nav badges are pushed, never polled** — the bell's unread count and the sidebar's "N running" count are one Alpine store (`core/js/nav-events.js`), seeded by the page render and updated by an SSE stream (`accounts/api/views.py`, `GET /api/nav/events`). Both counts go through the same helpers the first render uses — `accounts.context_processors.count_running` (which `query_running_jobs` wraps for the page) and `notifications.context_processors.query_unread_count` — so the seed and the stream cannot drift. The **seed carries the frames' own keys** (`state: { unread_count, running_runs }`, not the store's `unread`/`running` field names), so `nav-events.js` reads both through one `_applyState` and a key renamed on the Python side breaks both or neither; `test_the_page_seeds_the_store_with_the_keys_the_stream_sends` closes that loop across the template and the stream. `visible_to` is resolved **once per connection** (`_open_visible_runs`) rather than per recount — building it costs a platform-identity read plus a cache round-trip that cannot change for the life of a stream — and `count_running` counts over `values("pk")` so the visibility join's DISTINCT isn't spread over every `Run` column. The recount hops run `thread_sensitive=False`: the default mints one executor thread per request context and holds it until the response ends, which here is the duration cap, i.e. an idle OS thread per open tab. Those helpers **raise** on a `DatabaseError` and each caller picks its degradation: a page render shows 0, while the stream's `_counts` returns `None` and the frame is withheld — a reader cannot tell a fabricated zero from a real one, and pushing one blanks a badge that is still correct in the browser. Do not reintroduce an HTMX poll: the badge poll that existed before swapped `#notifications-bell` by `outerHTML`, which tore down the component owning the dropdown's `open` flag and closed an open dropdown every 10s. Frames are **whole-state snapshots**, so a reconnect needs no `Last-Event-ID` and the 300s duration cap doubles as the periodic resync that repairs a dropped poke — don't remove the cap. Wake-ups come from `core/ui_events.py` (Redis pub/sub): pokes carry only a `kind`, never a count, because the running count is per-viewer (`Run.objects.visible_to`) and each reader must compute its own; the reader recomputes both counts and withholds the frame when nothing moved, which is what makes the deliberately over-eager publishers cheap. That module is four objects, not a bag of functions — `Channel` (addressing), `UIEventKind` (vocabulary *and* the wire format — `as_payload`/`from_message`, so the two ends can't drift; not `encode`/`decode`, which a `StrEnum` inherits from `str`), `UIEventPublisher` (the `publisher` singleton: write side + fire-and-forget policy) and `UIEventStream` (read side) — over the `RedisConnections` in `core/redis.py`, which owns the lazy sync/async clients for the bus *and* the chat relay (`relay.get_redis` is a one-line delegation; tests still patch that name). Only the **sync** client carries a `socket_timeout` — it publishes inline on request and worker threads, where a wedged server would otherwise block forever — while the async one carries `socket_connect_timeout` alone, because its readers block on purpose (`PubSub.get_message(timeout=20)`, the relay's `xread(block=15000)`) and a shorter read deadline would cut those waits short. The SSE reader never touches a raw pub/sub message: it holds a `UIEventStream.for_user(pk)` and asks `wait_for_change(timeout)`, so channel names, burst coalescing (`COALESCE_S`, bounded by `ABSORB_MAX_S` so sustained poke traffic can't keep a reader absorbing instead of recounting) and junk tolerance stay on the bus. Every object takes an optional `connections=`, which is how tests inject a fake instead of patching module state. The recount is one `sync_to_async` hop (`_counts`) that returns its DB connection via `close_old_connections` on the way out — a stream idles for up to the duration cap, and `DB_POOL_MAX_SIZE` is 15 per process, so a connection held per open tab is the one thing that does not scale. Publishing is at **every** site that changes the state — the `Run` `post_save` receiver plus the writes that bypass it (`finalize_chat_run`'s `aupdate`, the `sync_stuck_runs` reaper's `.update()`), and `Notification`'s model methods plus `create_notification` rather than the views on top of them. `transaction.on_commit` stays at those call sites rather than inside the publishers, so `core.ui_events` needs no DB connection and a test that patches a publisher doesn't patch the deferral out of the code under test; every *sync* site wraps (the async `finalize_chat_run` cannot — it is outside the ORM's sync transaction machinery, and its own write is already awaited). The receiver's gate is a superset on updates (a full save carries no `update_fields`) but **exact on creates**, where `instance.status` is in hand: every non-chat path creates runs `READY`/`QUEUED`, which no reader's count includes. An unconfigured `DJANGO_REDIS_URL` is a supported shape (the test settings omit the Redis component): publishers no-op **silently** — a log there fires per write and broke `memory/test_extraction.py`, which asserts on the whole caplog — while the reader checks `redis_connections.configured` up front and answers with one warning plus `event: end` (`reason: "unavailable"`), the only case where reconnecting cannot help. Every *other* failure closes **without** a terminal frame, after a `retry: 30000`: `end` means "stop reconnecting", so using it for a transient bus drop froze the badges until the next page load, and the silent close is the same resync the duration cap already relies on. Because that retry means every reader comes back every 30s for the length of an outage, the reader's log level splits on `is_transient_bus_error` (the authority; `RedisError | OSError`, so `CancelledError` is never classified and keeps propagating) exactly as `_load_server_tools` splits on `_is_transient_mcp_error`: a dropped bus is one WARNING per tab per retry, and only a real bug gets `logger.exception`. `nav-events.js` streams only while the tab is visible (the poll it replaced was gated on `visibilityState`) — a hidden tab otherwise holds a worker, a recount per poke and one of the browser's six per-origin connections. The sidebar's label is a single msgid carrying a **brace** placeholder (`{count} running`) that `nav-events.js` fills client-side — never `%(count)s`: `{% translate %}` doubles every `%` before the catalog lookup, so a percent-style msgid misses and renders the untranslated English, which looks correct in the default locale and never fails CI (`make test` does not run `compilemessages`, and the `.mo` files are gitignored). `test_the_label_reaches_the_page_translated` installs a stub catalog so the assertion needs no compiled one. Going live also gave up the `blocktranslate` plural — pt uses identical forms, but a locale that does not would need the formed sentence sent per count.

**Chat composer anatomy** — one anatomy at every width: a sticky context row (repo · branch · MR pill) above the composer box, then a single action row (options `+`, progress pill, plain-text model label, icon-only Send/Stop). Everything else lives in a sheet — bottom sheet below 1100px, popover anchored above the trigger at ≥1100px; the model picker follows the same rule, via `.picker-popover` (see **Pickers** below). The mobile `.chat-summary` strip and the desktop `.chat-rail` are gone; do not reintroduce either. The progress pill is suppressed on **content** (no todos, no files, no diff → no trigger at all), so `latestTodos` and `filesTouched` are what decide whether it exists at all — and they are **plain props derived by one `Alpine.effect` armed in `init()`**, never getters that walk `turns`. Both failure modes are in that derivation. A getter that **caches across readers** is what hid the pill: Alpine tracks dependencies per effect, and ~15 always-mounted bindings read this state in one flush (the sheet is `x-show`-mounted, so its bindings stay live while it is closed), so a value cached "for the rest of the microtask" is handed to every reader but the first without touching `turns` — those bindings subscribe to nothing and never run again, and a `write_todos` landing mid-run reached none of them until a reload. A getter that **re-walks per read** is correct but costs a full transcript pass per binding — 20 per streamed `args` delta, which on a long run is seconds of main thread, since every `filesTouched` reader subscribes to the growing `args` of a streaming `write_file`. The effect subscribes once for all of them, so a pushed turn, an `args` delta and a landed result re-derive with no bookkeeping at the mutation sites; it must be `Alpine.effect` and not `$watch` (which compares the expression's value, and a mutation inside `turns` leaves its identity alone), it publishes **only when the derived list changed** by the fields a binding renders (`sameList`), and it compares against write-side closure state rather than the props it writes, so it never subscribes to its own output. Release it in `destroy()`. Parsing stays memoized per segment *and* per source string (`memoizePayload`), since `args` grows delta by delta. `test_progress_pill_reactivity.py` runs the real `init()` against a stand-in for that reactivity and is the only coverage of either half — one test that every binding sees the todos, one that a delta walks the transcript exactly once. Its `+/−` numbers come from `GitState.diff_stats`, measured by `GitChangePublisher` with `diff_line_stats` over the snapshot diff it already holds — never from the platform (`test_never_asks_the_platform_for_the_numbers` pins this), and never summed client-side from `editDiffCounts`, which double-counts repeat edits and scores `bash` edits as zero. The live agent/env pickers in the composer are `x-if`'d on `!thread`: left mounted they seed hidden inputs with the site default and get the next turn 409'd by the first-turn pin. The textarea is sized by its **content**, never by a fixed `rows`/`min-height` — a fixed second row is what put the action row a dead line below the text. `field-sizing: content` owns this, including the empty box, which it sizes to the *placeholder* (two lines at the widths where that translated string wraps, one everywhere else) — something `scrollHeight` cannot measure. `autosize()` is therefore gated on `NATIVE_FIELD_SIZING` and is only the polyfill for browsers without it, paired with the `:placeholder-shown` floor in `input.css`; don't ungate it, and don't re-add a JS max-height clamp — `max-height: 14rem` already caps the inline height. The "/" autocomplete (`.composer-autocomplete`, `chat/_command_menu.html`) is a full-width panel anchored above the composer box at **every** width — deliberately not a `.picker-popover` and not a bottom sheet, since it spans the composer's own width (no phone overflow to solve) and a sheet would cover the textarea being typed in. It sits on the surface-rise roster, holds its own `surfaceGroup` slot (separate from the sheets'), and its trigger regex (`SLASH_TOKEN_RE`) is the menu-while-token form of the bare-command parser in `slash_commands/parser.py` — keep the two in agreement.

**The composer's branch pill / `Session.ref`** — `Session.ref` is the branch a session is *working on*, not the one it started from: `apersist_session_ref` (`sessions/services.py`) moves it to the published MR's `source_branch` at the end of every **successful** run — off the streamer's final `STATE_SNAPSHOT` for a chat turn (`chat/api/streaming.py`), off the persisted checkpoint for a job run (`run_job_task`) and for an issue-webhook run (`IssueAddressorManager._address_issue`) — best-effort at every call site, because a cosmetic pointer must never fail a run that already published, and success-only, because a failed run's interim snapshot can name a branch it created but never committed to. That is not in tension with the pill preferring the MR below: a `merge_request` in the checkpoint means a publish landed, so its `source_branch` is a branch that exists on the remote — the column is just the conservative half. Those two functions plus `areset_session_ref` (the vanished-branch re-pin) are the **only** writers of that column outside session creation, and they live together in `sessions/services.py` — keep it that way. The ref a session *started* from is not lost: it stays on every `Run.ref`, which nothing rewrites. The pill itself is seeded from the **MR**, never from the column (`SessionDetailView`'s `thread_ref`), mirroring the live path's `_applyRepoState` — keep the two coupled. That is not cosmetic: the pill is what `submit()` sends as `X-Ref`, and the chat endpoint runs the turn on that header rather than on `session.ref`, so a pill left on the ref the agent moved off makes the next turn clone the wrong base, and it then opens a *second* MR rather than adding to the first — duplicated work, but never a lost turn. What guarantees that last part is `effective_merge_request` (`automation/agent/publishers.py`): **one** decision behind every MR a run may act on — the iid the prompt advertises and the target `aafter_agent` publishes to (`GitMiddleware._publish_target`), plus the post-crash draft in `BaseManager._recover_draft` — so a checkpointed MR whose `source_branch` isn't the checked-out ref is dropped at every end. Keep new callers on it rather than reading `state["merge_request"]` raw. They were split once — the prompt guarded, the two publishes not — and a turn that re-cloned the default branch pushed a commit that was a **sibling** of the MR branch's tip: rejected non-fast-forward, then `push_head_to(integrate_on_reject=True)` rebased it onto history the workspace was never based on, which conflicted and threw the turn's work away with a `GitPushStaleError` blaming a concurrent push that never happened — and the draft recovery then re-ran that same push and lost it again, so the issue got a bare "unexpected error" for work that was real. A second MR is the cheap failure here; a stale publish target is the expensive one. The drop's log level splits on **who chose the ref**, and is not to be flattened: on an *issue* run DAIV chose it itself (`Session.ref`), so a mismatch is its own continuity failing and gets `logger.error` — the only level this project turns into a Sentry event (`LoggingIntegration` runs at the default `event_level=ERROR` with `enable_logs=False`, so a WARNING reaches no one) — while every other scope stays WARNING, because a chat turn retargeting the branch pill mid-session hits the same guard legitimately and paging on it would train the signal away. The prompt path (`awrap_model_call`) deliberately logs *nothing*: it runs once per model call, and `_publish_target` reports the same condition once per turn. Every read of `state["merge_request"]` goes through `checkpointed_merge_request` (same module), whose `strict` flag is the *only* place that policy is chosen: `GitMiddleware` raises, while `BaseManager._recover_draft` degrades, because it is the last attempt at the work and its own catch-all would swallow the error and discard it. `core/checkpointer.py`'s docstring points at that one name — don't grow a second reader with its own wording, since an alert grepping the known message would miss it. *Issue*-webhook sessions carry no ref on the webhook — an issue is not a branch — so `address_issue_task` resolves one from the column via `aget_session_ref`, which is the only thing keeping a follow-up turn on the branch the previous turn published to; *MR*-webhook sessions store the MR's `source_branch` at creation (`{gitlab,github}/api/callbacks.py`), so their column is already the working branch and the addressors need no read of their own. A stale MR in the checkpoint (branch merged and deleted) self-heals on the next turn: the clone falls back to the default branch, `areset_session_ref` re-pins the row and the `ref_fallback` event moves the pill.

**Wrapping chat text** — `.chat-text` wraps with `overflow-wrap: anywhere`, never `break-word`: only `anywhere` shrinks a box's *min-content* width, and chat text is sized intrinsically (the user bubble's inner text is a flex item under `align-items: flex-start`), so `break-word` leaves the box as wide as a pasted URL and the text paints outside the bubble — clipped rather than scrollable, since `<main>` sets `overflow-x: hidden`. Inheriting it is the point: assistant prose, inline `code` chips and markdown table cells each overflowed on their own before it, while `pre` keeps the UA's `white-space: pre` and so still scrolls horizontally instead of re-wrapping code. The one exemption is `th` (`overflow-wrap: normal`) — headers are short enough that holding one whole can't widen the table. Nothing enforces any of this automatically: a grep over the stylesheet would miss the cascade, and a Tailwind wrapping utility on a `.chat-text` element (`break-normal`, `wrap-normal`) silently reverts it — the utilities layer outranks the components layer this lives in.

**Per-thread MCP servers** — `MCPServer.status` is tri-state (`active` / `on-demand` / `disabled`); there is no `enabled` boolean. `deduped_pool_rows` is the pool (everything not `disabled`, globals shadowing same-named user rows), `is_default` marks the `active` subset, and `build_runtime_servers` loads the defaults with `Session.mcp_overrides` (`{name: "on"|"off"}`) applied. Stored values are **pool-relative diffs, never name sets**: `diff_selection` writes only deviations and `effective_selection` reads them back, so an admin's status flip re-resolves instead of freezing the thread, and a stale `"on"` for a deleted server self-heals. `disabled` is absolute — an override can never re-enable one. Unhealthy servers stay *in* a selection (dropping them would evict them from the thread permanently once the outage cleared) and render inert rather than unchecked. Unlike the model and the env the selection is **not** pinned on the first turn: any turn may retune it, and a *retune* lands *after* `SessionLock.try_claim` so a rejected duplicate leaves no memory of a turn that never ran (a first turn's selection is persisted with the session row, on the same terms as the model and the env). Bounds live in `parse_server_names` (shared by the chat endpoint and `MCPSelectionField`), and the shadow warning fires only on the runtime path (`warn_shadowed=True`) — the display paths run per page render.

**Bot labels** — `daiv` triggers agent, `daiv-max` uses max model, `daiv-auto` enables auto-addressing. Constants live in `daiv/core/constants.py`; do not hardcode the strings.

**Per-repo agent memory** — agent reads `.agents/AGENTS.md`; custom skills from `.agents/skills/`; subagents from `.agents/subagents/`. A custom skill with the same name as a built-in **shadows** the built-in (runtime + storage are consistent; the UI flags the card with "Overrides built-in"). The `code-review` skill additionally reads `.agents/review-rules.md` for per-repo review rules (with `AGENTS.md` as a secondary source).

**Repository memory ("dreaming")** — `MemoryEntry` rows are the source of truth; `RepositoryMemory.content` is a render cache produced by `render_memory_document` (`memory/render.py`), never model-generated. Entries are append-only — `entry.supersede(successor)` / `entry.confirm(when)`, never in-place edits or deletes — and `memory_max_lines`/`memory_max_bytes` are enforced by `prune_to_budget`, never by slicing the rendered document. The structured-output schemas (`memory/schemas.py`) deliberately carry **no** pydantic length or size constraints: parsing is all-or-nothing, so one over-long field would discard a whole valid batch; limits are checked per item instead.

**Django settings** — test module is `daiv.settings.test`; `NINJA_SKIP_REGISTRY=true` is injected automatically in tests.

**Python 3.14 except syntax (PEP 758)** — `except E1, E2:` is valid and equivalent to `except (E1, E2):`. Ruff canonicalises to the unparenthesised form, so do NOT "fix" it back to parens; both run, and rewriting is just churn.

**Sandbox wire schemas** — `daiv/core/sandbox/schemas.dump.json` is the canonical sandbox-side schema dump. The `tests/unit_tests/core/sandbox/test_schema_consistency.py` test will fail if the daiv-side schemas drift from it. Regenerate after any change to `daiv_sandbox/schemas.py` in the [daiv-sandbox](https://github.com/srtab/daiv-sandbox) repo:

```bash
# from a checkout of the daiv-sandbox repo (PYTHONPATH is required — that repo declares no build
# backend, so `uv run` never puts `daiv_sandbox` on sys.path)
PYTHONPATH=. uv run --all-extras python scripts/dump_schemas.py \
    > /path/to/daiv/daiv/core/sandbox/schemas.dump.json
```

A type the sandbox deletes disappears from the dump; if the daiv side still models it, delete the
dead model rather than adding an exemption to that test. Note the comparison normalizes
`title`/`description` away — field docstrings are *not* pinned and can silently drift from the
sandbox's own wording.

**MCP tool-load degradation** — `_load_server_tools` (`daiv/automation/agent/mcp/toolkits.py`) degrades to `[]` and never raises. Anticipated/transient failures log at **WARNING** (no traceback) so an external outage doesn't mint a Sentry error event per agent run; only genuinely unexpected errors fall through to `logger.exception` (ERROR + traceback). The canonical transient set lives in `_is_transient_mcp_error` (the authority — don't re-enumerate it here): a bare `TimeoutError` is caught earlier by its own `except TimeoutError:` clause, and the classifier covers upstream 5xx (`httpx.HTTPStatusError`), a broken MCP stream (`anyio.BrokenResourceError`, when anyio is importable), and a `BaseExceptionGroup` whose leaves are *all* transient (how anyio surfaces TaskGroup teardown). `CancelledError` is a `BaseException` → a group containing it is a `BaseExceptionGroup` that `except Exception` never catches, so outer cancellation keeps propagating; don't "fix" this.

**Streamed `response_metadata` strings concatenate** — `merge_dicts` appends same-key strings across message chunks, and `langchain_openai` re-stamps `finish_reason` / `model_name` / `system_fingerprint` / `service_tier` on every chunk carrying a finish reason, so a provider that sends two finish chunks (OpenRouter, for some upstreams) accumulates `"z-ai/glm-5.2z-ai/glm-5.2"`. Price and context window are both looked up *by name*, so that silently dropped the turn's cost and the chat context meter's scale. The `daiv/automation/agent/chat_models.py` **module docstring owns the full explanation** — read it there rather than re-deriving. What matters outside it: the fix is two layers, and neither is redundant — `ChatOpenRouter._stream`/`._astream` keep corruption out of checkpoints and traces, while `collapse_repeated_model_name` (`daiv/automation/agent/usage_tracking.py`) repairs on read, which is the *only* cover for a gateway configured as `provider_type=OPENAI` (a plain `ChatOpenAI` from `init_chat_model`, which never passes through the subclass) and for rows written before the fix. **Never read `response_metadata["model_name"]` raw** — go through `message_model_name`, or the bug comes back at the next multi-finish-chunk provider; `sessions/spend.py` collapses stored keys directly for the same reason. `CostAwareUsageMetadataCallbackHandler.on_llm_end` *replaces* rather than extends the base method, because the base keys its public `usage_metadata` off a raw read. Two test footguns: `test_the_pinned_key_set_is_what_upstream_stamps` derives the corrupted key set by diffing a 1- against a 2-finish-chunk stream through *stock* `ChatOpenAI`, so a fifth key added upstream fails the suite instead of silently doubling — which means `openai_stream.chunk()` must stay free of a `usage` key, or `token_usage` joins that derived set.

**Assistant messages the model didn't write** — a middleware that returns a user-facing `AIMessage` without a model call (a slash command reply, a `LoopBreakerMiddleware` stop) must build it with `streamed_assistant_message` (`daiv/automation/agent/utils.py`), not `AIMessage(...)` directly. Nothing else emits `TEXT_MESSAGE_*` for it: the AG-UI translator synthesizes text frames only from `on_chat_model_stream`, so a plain state-injected message reaches the browser only inside the terminal `MESSAGES_SNAPSHOT` — which `chat-stream.js` has no handler for — and the turn paints empty until a reload rebuilds the transcript from the checkpoint. The helper dispatches DAIV's own `ASSISTANT_MESSAGE_EVENT`, which `RuntimeContextLangGraphAGUIAgent._assistant_message_frames` (`daiv/chat/api/streaming.py`) translates, keeping `daiv/automation/` at **zero** `ag_ui`/`copilotkit` imports. Both halves of that wire contract — name *and* payload — live in `daiv/automation/agent/events.py`; build and parse through its helpers rather than repeating the keys, since the consumer degrades an unreadable payload to "no frames" and a key renamed on one side alone is back to a silent empty turn. `test_a_middleware_message_reaches_the_stream_as_text_frames` is the only test that closes that loop; per-side tests assert their own literals and stay green through a rename. `ag_ui_langgraph` ships an equivalent handler for its own `manually_emit_message` and adopting that wire name would need no import — it is forked anyway because upstream hard-subscripts `event["data"]["message_id"]` (one malformed payload kills the run) and because a rename of that undocumented enum would silently stop these messages rendering, which is the very failure this exists to fix. Copilotkit's `copilotkit_emit_message` is separately unusable: its handler builds the same three frames and then discards them. Messages addressed to a *parent agent* rather than the user (LoopBreaker's `terminal="error"`, whose `ERROR:` prefix the code-review orchestrator parses) stay unstreamed on purpose.

**Task queues** — `db_worker` claims one task and runs it to completion before looking at the queue again, so concurrency is worker *processes* and `priority` only reorders what is waiting; it never preempts what is running. Short user-visible work (titling, `classify_run_task`, notification delivery) therefore runs on the **`interactive`** queue and everything long stays on `default` — sharing them is what left sessions reading "generating title…" an hour after creation, behind agent runs that hold a worker for minutes (`run_job_task` can sleep up to `LOCK_WAIT_TIMEOUT_S` inside the task waiting on the session lock). Queue names and the interactive queue's priorities live in `core/constants.py`; a queue must also be declared in `TASKS["default"]["QUEUES"]` (`settings/components/tasks.py` — the test settings override only `BACKEND` and inherit the rest), since the backend validates `queue_name` in `Task.__post_init__` — an undeclared one raises at *import* time, not at enqueue. Workers are told which queues to serve by the first argument to `docker/*/app/start-worker`, which defaults to `*`, `db_worker`'s own "every queue", so an unedited deployment strands nothing. `tests/unit_tests/test_task_queues.py` closes that loop across the tasks, both settings, the compose file and both stacks in the deployment guide.

**`thread_id` contract** — callers of `run_job_task` must supply a non-empty UUID `thread_id`. The `Activity` row and LangGraph checkpointer share this key; a missing ID breaks chat resume.

**Pipeline watch layering** — `daiv/sessions/pipeline_watch/` is layered, and the layering is the
design: `judgment` and `policy` are pure, `platform` holds the package's **only** `RepoClient`, and
`store` is the **only** reader and writer of `Session.watch_*`. `PipelineWatch` orchestrates them
through constructor-injected collaborators, which is how tests fake CI while the store runs against
the real database — do not reintroduce `monkeypatch` on module-level names. `WatchPlatform` is
per-repository (constructing a GitHub client costs a live installation lookup), which is why
`WatchReconciler` takes factories rather than instances: one sweep spans repositories.
`WatchStore.atransition` is the single writer of a watch's state *transitions*, and only its winner
posts the accompanying MR comment — two events finishing together both clear their checks off their
own stale read, and no constraint dedupes a duplicate MR comment.

**Skill asset paths** — inside a skill, paths like `scripts/foo.py` resolve to `<location>/<skill-name>/scripts/foo.py`, **not** the bash CWD (repo root). Always invoke skill scripts by absolute path. See `daiv/automation/agent/skills/skill-creator/scripts/init_skill.py` as the reference.

**Floating surfaces** — popovers, sheets and dropdowns all rise into place on open, via the shared `surface-rise` keyframe. The roster of surface classes is one grouped rule at the top of `input.css`; `.surface-rise` is the hook for the dropdowns built from utilities alone. Put new surfaces on that roster instead of hand-rolling motion, tune travel with `--surface-rise-from` (sheets come from further out than a menu), and never pair it with Alpine's `x-transition` — both drive `opacity`/`transform` and fight over the same frames. Side drawers (`_env_drawer.html`, `_template_gallery.html`, `_env_paste_overlay.html`) keep `x-transition` on purpose: they slide in horizontally and animate on leave too. **Pickers** — every `.picker-popover` (model, repo, branch, env, subscriber, config section) is an anchored popover at ≥1100px and a **bottom sheet below it**, on every screen that hosts one — a trigger anywhere but hard left puts a 320px panel over the right edge of a phone, and no anchor tweak covers every case. Geometry belongs in CSS (`.picker-popover`, `--wide`, `--inset`), never as `left-*`/`w-*` utilities on the element: Tailwind's utilities layer outranks every component rule regardless of selector, so a utility anchor survives into widths where it doesn't fit — that is what put the model popover off the right edge of a phone. A layout that swaps *with* a picker — a sidebar giving way to the sheet that stands in for it, as on the configuration page — switches on `--breakpoint-popover` (the `popover:` variant), never on `lg`: `lg` is 64rem and crosses the fixed 1100px once the root font-size passes 17.19px, opening a band where the trigger shows while the surface is still an anchored, headless popover. `test_the_sheet_breakpoint_is_a_single_number` pins the token to the media query. A sheet is **flush to the viewport edges only below `sm:`** — the width where the sidebar appears. From there up (tablets, phones in landscape) both sheet families are inset to the content column and capped at `--sheet-width-cap`, centred in what is left: a flush sheet at those widths spans the nav as well, and a browser that clips a fixed panel at the scrolling `<main>` it lives in cuts the crossing half off — which is how this was reported, every line of a tablet-landscape sheet trimmed mid-word. The cap is a design constant rather than shell geometry, so past roughly an 800px viewport the sheet is *narrower* than the composer it opened from, not aligned with it — don't describe it as lining up. That regime is one **`:root` switch** (`--sheet-inset-start`, `--sheet-inset-end`, `--sheet-width-cap`, `--sheet-side-border`), the move the reduced-motion block beside it already makes: every sheet reads those with the flush value as a `var()` fallback, so the switch needs no particular source position and insetting a third sheet family is a `var()` rather than another roster. Do **not** go back to re-declaring the roster in a media query — the rule that did sat 550 lines and one `@layer components` block away from the `.composer-sheet` it governed and won by source order alone, which is invisible at both ends. Its lower bound is `theme(--breakpoint-sm)` — the same value `sm:` itself compiles from, not the `40rem` it resolves to — so the switch cannot reorder against the sidebar's own `sm:flex` the way `lg` does against 1100px. The scrim is deliberately *not* on this regime: `.sheet-backdrop` stays full-viewport, so the nav dims behind a column-scoped panel and a click on it still dismisses. `test_a_bottom_sheet_never_opens_under_the_sidebar` pins the switch and then *discovers* the sheets — every viewport-anchored, bottom-anchored rule in the stylesheet has to read every token the switch declares, with a fallback (without one the flush form resolves to nothing, not to flush), and the scrim is exempt by name, so a third family cannot ship flush and no roster needs updating; `test_the_sheet_inset_tracks_the_shell_it_dodges` closes the loop back to the shell — the sidebar sizes itself from `--app-sidebar-width` (never a literal `w-60`) and `<main>` pads by `sm:px-(--app-content-gutter)` (never `px-6` spelled again), each asserted against its own opening tag because `<header>` carries the same gutter and `sm:flex-col` contains `sm:flex`. The general alternative — `contain: layout` on the shell's content column, which would make *every* fixed surface resolve against it and need no tokens at all — is deliberately not taken: it makes that element a stacking context (the footgun `test_surface_stacking.py` exists for) and would quietly re-scope the side drawers' scrims from the app to the column. Reach for it only with visual checks across every drawer and sheet, not as a fifth `--sheet-*` token. Rows inside a popover are the shared `.env-popover__row` family (`--selected`, `__row-body`/`__row-head`/`__row-name`, `__check`), not per-picker utilities. Every popover includes `core/_sheet_head.html` (title + dismiss, `display: none` above 1100px) because a sheet covers the trigger that would otherwise dismiss it — the same partial the composer sheets use, with `surface="composer-sheet"`; pass `close_expr` since each surface names its close differently. It also includes `core/_sheet_backdrop.html` — the scrim (`.sheet-backdrop`, shared with the composer's own sheets and switching off at the same 1100px, from its own media block rather than the composer's), one per popover, driven by that surface's *own* `x-show` expression and rendered **outside** the surface with no stacking context between the two — a sibling in the pickers, three levels up in the dock for the composer's. Inside the surface the fixed overlay inherits its stacking context and paints over the panel's own background, and takes the panel as its containing block for as long as `surface-rise` holds a transform. The scrim carries **no handler**: a click on it is outside the surface by construction, so the `@click.outside` every one of them already has is what dismisses — which is why `test_every_popover_dims_the_page_behind_its_sheet` checks for that attribute beside the expressions, and why the partial takes no `close_expr`. It dims and swallows clicks, nothing more: the page behind an open sheet still scrolls and still takes Tab. Two things keep the sheet halves working, both pinned by `tests/unit_tests/`: an animation that moves a `transform` fills **`backwards`, never `both`/`forwards`** — a forward fill resolves `transform` to a matrix rather than `none` (identity is still a matrix), and the animated card then becomes the containing block for every `position: fixed` descendant, which is what opened the sheets at the bottom of the *page* instead of the viewport; and every surface on the roster joins `core/js/surface-group.js` — `this._announceOpen = surfaceGroup.join(() => this.close())` in `init()`, `this._announceOpen()` on open, no teardown (one slot, and closing an already-closed surface is a no-op) — so only one is ever open. Without it none of them hears its neighbours, since triggers carry `@click.stop` to survive their own `@click.outside`, and two sheets render stacked on the same edge. Membership is *floating* surfaces only: a disclosure that expands in place inside a sheet (the env picker's `variant="sheet"`) must not announce, or it dismisses the sheet containing it. Nothing **enclosing** a surface may carry `opacity`, `transform`, `filter` or `backdrop-filter`, in a rule or as a utility: each one makes that element a stacking context, so the surface's `z-index: 60` stops outranking the scrim's 55 and the panel opens *under* the dim, and an `opacity` also fades the panel's own background so the page behind shows through it. That is why the composer's in-flight fade goes control by control (`.chat-composer--sending .composer-send`, …) rather than once on `.chat-composer`. `test_surface_stacking.py` pins it repo-wide rather than per app — the same picker ships into a dozen pages and the bug lives in the *ancestor chain*, which differs on each — by rendering one page per way the app wraps a surface and walking every ancestor of every one it finds. A roster of controls has the failure the single rule did not, so the other half is pinned too: `test_every_composer_control_goes_inert_while_a_turn_is_in_flight` reads the faded classes back out of the stylesheet and checks them against what the composer renders, with `.chat-jump` exempt by name (it floats above the box, over the transcript). Animations are deliberately out of scope on both — `test_transform_animations_never_fill_forwards` already pins every keyframe that moves a transform to `backwards`, so the property is released when it ends and no lasting stacking context survives.

**Icons in templates** — never hand-roll an inline `<svg>` for a UI icon. Use `{% load icon_tags %}{% icon "name" "css-classes" %}`; see `DESIGN.md` §Icon System for the mechanism and the icon directory. Exceptions (keep inline): animated spinners, SVGs that need `<title>`/Alpine `:class` on the element itself, and brand/logo `<img>` tags.

**Dashboard page width** — the sidebar is a fixed `--app-sidebar-width` (15rem) from `sm:` up, so a `sm:` layout switch fires when the content area is only ~350px — *narrower* than the phone layout it replaces. Anything that should sit side by side only while both halves fit (a page title and its actions, a list row and its trailing controls) wraps on content instead: grow the leading block, floor its `flex-basis`, and let the rest drop below — `.page-header` / `.page-header__title` / `.page-header__actions`, documented in `DESIGN.md` §Page Header. Reach for a breakpoint only when the switch doesn't depend on the two fitting, and derive it from the content area rather than the viewport.

**Views split by content type** — server-rendered HTML (dashboard pages, forms) lives in `daiv/<app>/views.py` as **CBVs** subclassing `View` / `TemplateView` / `ListView` / `UpdateView` with `LoginRequiredMixin` / `AdminRequiredMixin`. JSON endpoints (including those consumed by dashboard JS like autocompletes and the agent-picker catalog) live in `daiv/<app>/api/views.py` (or `api/router.py` — both names exist) as a **django-ninja `Router`** with `auth=django_auth` for session callers, registered on the central `NinjaAPI` in `daiv/daiv/api.py` (`api.add_router("/<app>", <app>_router)`). Set `url_name="..."` on each route and reverse via `{% url 'api:<route_name>' %}` from templates (or pass the URL into JS as an init prop instead of hardcoding `/api/...` paths); see `daiv/automation/api/views.py` + `_agent_picker.html` for the reference pair.

**Filtered list views** — do **not** hand-roll `request.GET` parsing or a manual `Paginator` in a `TemplateView`. Declare a `django_filters.FilterSet` in `daiv/<app>/filters.py` (filters declared explicitly, `Meta.fields = []` to disable auto-generation) and use a `FilterView` with `filterset_class`, `paginate_by`, and `strict = False` (an invalid param like `?status=bogus` then drops that filter instead of blanking the list). Echo selected values back to the template via `cleaned = ctx["filter"].form.cleaned_data if ctx["filter"].form.is_valid() else {}`. Reference pairs: `daiv/activity/filters.py` + `ActivityListView`, `daiv/accounts/filters.py` + `UserListView`, `daiv/memory/filters.py` + `MemoryDetailView` (a hybrid detail page that is a `FilterView` over a sub-list — it overrides `get()` to stash the parent object + unfiltered total for the 404 guard before `super().get()`). **Exception:** a list whose rows are a union/merge of multiple tables rather than a single-model queryset legitimately stays a `TemplateView` (e.g. `MemoryListView`, which unions `MemoryObservation` aggregates with `RepositoryMemory` rows) — `ListView`/`FilterView` only fit a single base queryset.
